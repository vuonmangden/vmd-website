## 2. Bối cảnh

Tech Spec §10.6 định nghĩa bảng `customers` tách khỏi booking để chuẩn bị CRM Phase 2. Execution Plan §9 mô tả: "Tạo customer, chuẩn hóa phone/email, tìm khả năng trùng và lưu consent."

Bảng `customers` là nền tảng cho Booking (BKG-004), BBQ (BBQ-004), và CRM (Phase 2). Master Architecture §8.2 / §11 mô tả customer identity resolution.

## 3. Mục tiêu

- Migration tạo bảng `customers` theo Tech Spec §10.6.
- Service chuẩn hóa phone (E.164) và email (lowercase).
- Service phát hiện khả năng trùng (cùng phone hoặc email).
- Lưu consent (marketing_consent, privacy_consent_at).
- Sinh customer_code tự động, unique.
- Emit domain event `customer.created` qua outbox.

## 4. Ngoài phạm vi

- Admin API endpoints cho customers (OPS-004).
- Customer admin UI.
- Customer identity resolution / merge (Phase 2).
- Booking creation flow (BKG-004).
- Customer authentication (khách không cần đăng nhập Phase 1).

## 6. User story / Use case

**Là** hệ thống booking, **tôi muốn** tạo và quản lý hồ sơ khách hàng, **để** liên kết booking/BBQ với khách và chuẩn bị CRM.

Luồng chính:

1. Khách nhập thông tin (tên, phone, email) trong booking flow.
2. Service chuẩn hóa phone và email.
3. Service kiểm tra khả năng trùng.
4. Tạo customer mới hoặc liên kết customer hiện có.
5. Emit `customer.created` event.

## 7. Quy tắc nghiệp vụ

1. Phone chuẩn hóa theo E.164 VN (+84xxxxxxxxx).
2. Email chuẩn hóa lowercase (citext xử lý case-insensitive).
3. Không UNIQUE trên phone/email (gia đình có thể dùng chung) — §10.6.
4. customer_code unique, tự sinh.
5. marketing_consent default false.
6. Soft delete qua deleted_at.
7. Không log PII đầy đủ.
