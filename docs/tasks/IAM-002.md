# IAM-002 — Roles and Permissions

## 1. Thông tin task

- **Task ID:** `IAM-002`
- **Tên task:** Roles and Permissions
- **Trạng thái:** In progress
- **Branch:** `feat/iam-002-roles-permissions`
- **Dependency:** IAM-001 (Done)

## 2. Mục tiêu

Triển khai hệ thống phân quyền dựa trên role theo Tech Spec §33. Mỗi staff member có một role, mỗi role có danh sách permissions. Backend kiểm tra permission trước khi cho phép thao tác.

## 3. Phạm vi

### Trong phạm vi

- Định nghĩa 5 roles: `super_admin`, `manager`, `reception`, `marketing`, `accountant`.
- Định nghĩa permission constants theo §33 RBAC matrix.
- `RolesGuard` — kiểm tra role của staff.
- `@Roles()` decorator — gắn required roles lên endpoint.
- `@Permissions()` decorator và `PermissionsGuard` — kiểm tra permission chi tiết.
- Permission mapping: role → permissions.
- Unit tests cho guards và permission logic.
- Seed initial super_admin staff member.

### Ngoài phạm vi

- Admin route protection (IAM-003).
- UI hiển thị role/permission.
- Quản lý động role/permission (Phase 2).

## 4. Yêu cầu kỹ thuật

### 4.1 Roles (§33)

```typescript
const StaffRole = {
  SUPER_ADMIN: 'super_admin',
  MANAGER: 'manager',
  RECEPTION: 'reception',
  MARKETING: 'marketing',
  ACCOUNTANT: 'accountant',
} as const;
```

### 4.2 Permissions

Permissions derived from §33 matrix. Mỗi permission là một string constant.

### 4.3 Guards

- `RolesGuard`: check staff.role against `@Roles()` metadata.
- `PermissionsGuard`: check staff.role's permissions against `@Permissions()` metadata.
- Cả hai guard đều mặc định từ chối nếu không có metadata (public endpoints opt-in).
