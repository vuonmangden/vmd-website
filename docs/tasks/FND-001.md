# FND-001 — Khởi tạo Monorepo

## 1. Thông tin task

- **Task ID:** `FND-001`
- **Tên task:** Khởi tạo monorepo Vườn Măng Đen Phase 1
- **Milestone:** Milestone 1 — Foundation
- **Mức ưu tiên:** P0
- **Trạng thái:** Ready
- **Phụ thuộc:** Không có dependency code; toolchain đã được chốt tại `ADR-001-FOUNDATION-TOOLCHAIN.md`
- **Branch:** `chore/fnd-001-initialize-monorepo`

## 2. Bối cảnh

Vườn Măng Đen cần một repository thống nhất để phát triển Public Web, Admin Web, API và Worker theo kiến trúc Modular Monolith. Task này chỉ tạo nền tảng kỹ thuật tối thiểu có thể cài đặt, kiểm tra và build; chưa triển khai nghiệp vụ phòng, booking, BBQ, payment, CMS hoặc notification.

## 3. Mục tiêu

- Tạo cấu trúc monorepo chuẩn cho bốn ứng dụng và các package dùng chung.
- Thiết lập pnpm workspace, Turborepo và TypeScript theo `docs/03_TECHSPEC_PHASE_01.md`, mục 3.2–3.3, và `docs/decisions/ADR-001-FOUNDATION-TOOLCHAIN.md`.
- Cung cấp lệnh thống nhất để lint, type check, test và build toàn repository.
- Tạo tài liệu khởi động và mẫu biến môi trường an toàn.
- Tạo nền tảng tối thiểu để FND-002 và FND-003 tiếp tục mà không phải tái cấu trúc lớn.

## 4. Ngoài phạm vi

- Không tạo schema nghiệp vụ hoặc migration production.
- Không tích hợp Supabase Auth, SePay, email hoặc Zalo thật.
- Không triển khai UI hoàn chỉnh, design system hoàn chỉnh hoặc trang nghiệp vụ.
- Không triển khai Docker Compose, PostgreSQL, Redis hay Mailpit; thuộc FND-002.
- Không cấu hình pipeline CI đầy đủ; thuộc FND-003.
- Không xây API foundation hoàn chỉnh; thuộc FND-004.
- Không thêm dependency ngoài nhu cầu trực tiếp của task.

## 6. User story

**Là** đội phát triển Vườn Măng Đen, **tôi muốn** có monorepo có cấu trúc và toolchain thống nhất, **để** các module Phase 1 được phát triển, kiểm thử và build nhất quán.

Luồng chính:

1. Clone repository sạch.
2. Cài đúng phiên bản runtime/package manager.
3. Cài dependencies bằng lockfile.
4. Chạy lint, type check, test và build từ root.
5. Khởi chạy từng application shell theo README.

Luồng lỗi:

- Thiếu runtime hoặc sai phiên bản: lệnh phải báo rõ yêu cầu.
- Thiếu biến môi trường: ứng dụng phải báo tên biến thiếu mà không in secret.
- Dependency/toolchain xung đột với Master Architecture: dừng và tạo câu hỏi/ADR, không tự thay stack.

## 7. Quy tắc kỹ thuật bắt buộc

1. Dùng kiến trúc Modular Monolith; không tách microservice.
2. Dùng pnpm workspace và Turborepo như kế hoạch đã thống nhất.
3. TypeScript strict cho code mới; mọi ngoại lệ phải có lý do.
4. Một lockfile ở root; không tạo lockfile riêng trong từng app.
5. Không hard-code secret; không commit `.env`.
6. `.env.example` chỉ chứa tên biến và giá trị giả an toàn.
7. Public Web/Admin Web không được có Service Role Key hoặc database URL.
8. Package dùng chung không được phụ thuộc ngược vào application.
9. Không tạo business logic giả để làm demo trong task foundation.
10. Lệnh root phải có thể chạy theo dependency graph và trả exit code đúng.

### Toolchain đã chốt

- Node.js: dòng `24 LTS`.
- Package manager: pnpm, quản lý bằng Corepack và khóa phiên bản chính xác trong `package.json`.
- Monorepo: Turborepo.
- Public Web và Admin Web: Next.js `16.2.x`, App Router, TypeScript.
- Backend API: NestJS `11.x`, TypeScript.
- ORM dự kiến: Prisma ORM `7.x`; chưa kết nối database trong task này.
- Database dự kiến: PostgreSQL `16.x` hoặc managed-compatible; chưa khởi tạo trong task này.
- Styling: Tailwind CSS + design tokens.
- Package scope: `@vmd/*`.
- Vitest cho Public Web, Admin Web và shared packages.
- Jest cho NestJS API và Worker.
- Supertest cho API integration; Playwright cho E2E ở các task phù hợp.
- Với pnpm, TypeScript, Turborepo, ESLint và các công cụ chưa khóa major trong Tech Spec: chọn phiên bản stable tương thích tại thời điểm scaffold, khóa chính xác trong repository và ghi vào báo cáo cuối task. Không tự nâng major sau đó.

## 10. Yêu cầu từng application

### `apps/web`

- Public Web shell có thể start và build.
- Có trang placeholder kỹ thuật tối thiểu, không dùng nội dung nghiệp vụ giả.
- Không chứa credential server-only trong client bundle.

### `apps/admin`

- Admin Web shell có thể start và build.
- Chưa triển khai login/RBAC; phải ghi rõ chưa có khả năng production.
- Không coi việc ẩn route/UI là authorization.

### `apps/api`

- NestJS application shell có thể start và build theo stack đã chốt.
- Có endpoint kỹ thuật tối thiểu chỉ khi Tech Spec cho phép; health foundation đầy đủ thuộc FND-004.
- Không kết nối database hoặc provider thật trong task này.

### `apps/worker`

- Worker shell có thể start và build.
- Chưa kết nối queue/provider thật; thuộc các task sau.
- Không chạy timer hoặc gửi notification giả ngoài kiểm soát.

## 11. Scripts và developer experience

```text

pnpm typecheck

```

- Tên script cuối cùng phải thống nhất trong README và CI tương lai.
- `dev` phải nêu rõ cách chạy tất cả hoặc từng app.
- Build không phụ thuộc secret production.
- Lệnh phải hoạt động trên môi trường phát triển đã được dự án xác nhận.

## 12. Mẫu biến môi trường

`.env.example`:

- Chỉ khai báo các biến thực sự cần cho shell hoặc để chuẩn bị rõ cho task tiếp theo.
- Phân biệt biến public và server-only bằng naming convention.
- Có comment ngắn về mục đích, không ghi giá trị thật.
- Không được chứa Service Role Key, password, token, webhook secret hoặc tài khoản thật.

Nếu validation env được thêm, test phải chứng minh secret không bị in ra trong lỗi.

## 13. Yêu cầu bảo mật

- `.gitignore` chặn `.env`, key, certificate, log và artifact nhạy cảm phù hợp.
- Secret scan không phát hiện credential trong code hoặc fixture.
- Client bundle không chứa biến server-only.
- Dependency pin/lockfile deterministic.
- Không bật CORS `*`, tắt SSL/RLS hoặc thêm bypass auth dù chưa triển khai auth.
- Package script không chứa lệnh phá hủy dữ liệu hoặc production.
- Placeholder phải được ghi rõ là non-production; không tạo mock endpoint có thể bị dùng nhầm.

## 15. Acceptance criteria

- [ ] Given repository sạch và runtime đúng phiên bản, when chạy `pnpm install`, then dependencies được cài bằng một lockfile mà không cần thao tác thủ công không được tài liệu hóa.
- [ ] Given dependencies đã cài, when chạy các lệnh root cho lint, type check, test và build, then tất cả hoàn thành với exit code thành công.
- [ ] Given bốn application, when chạy theo README, then mỗi app shell khởi động đúng vai trò và không yêu cầu secret production.
- [ ] Given một developer mới, when đọc README, then có thể hiểu cấu trúc, prerequisites, lệnh cơ bản và ranh giới Phase 1 foundation.
- [ ] Given repository được scan, when kiểm tra secret và client bundle, then không có credential hoặc biến server-only bị lộ.
- [ ] Không có nghiệp vụ phòng, booking, BBQ, payment, CMS hoặc notification được triển khai ngoài phạm vi.
