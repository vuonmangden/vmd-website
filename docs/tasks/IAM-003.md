# IAM-003 — Admin Route Protection

## 1. Thông tin task

- **Task ID:** `IAM-003`
- **Mức ưu tiên:** P0
- **Trạng thái:** Review (`IMPLEMENTATION_APPROVED`)
- **Phụ thuộc:** `IAM-002`
- **Branch dự kiến:** `codex/iam-003-admin-route-protection`

## 2. Mục tiêu và phạm vi

- Bảo vệ route admin ở backend bằng authentication + permission guard và ở frontend bằng trusted `/auth/me` state.
- Có loading, unauthorized, forbidden, session-expired và provider-unavailable state; không chỉ ẩn nút.
- Owner: admin auth boundary/routes, API admin guard/decorator integration và test trực tiếp; không thêm migration.

## 3. Quy tắc và tests

- Backend luôn là điểm quyết định; deep link/refresh/direct API đều bị chặn đúng 401/403.
- Session hết hạn thử refresh một lần an toàn; thất bại thì xóa session memory và về login.
- Test role × protected sample endpoint, missing/malformed/expired/revoked token, forbidden permission, URL trực tiếp, loading/error/mobile/accessibility.
- Không log token/PII; OpenAPI bearer + permission contract; full lint/typecheck/test/build và hosted CI đạt.

## 4. Bằng chứng implementation — 2026-08-11

- Backend thêm `AdminAuthGuard` để xác minh token và nạp trusted actor trước `PermissionsGuard`; hai endpoint mẫu `/admin/access` (`report.read`) và `/admin/access/users` (`user.manage`) có OpenAPI 401/403.
- Admin Web bảo vệ route gốc bằng trusted `/auth/me`, chỉ kiểm quyền từ actor server trả về; access token/refresh token chỉ giữ trong memory.
- Access token hết hạn được refresh đúng một lần rồi gọi lại `/auth/me`; refresh thất bại xóa session và chuyển về `/login`.
- UI có loading, session-expired/unauthorized, forbidden và provider-unavailable state với `role=status`/`role=alert`; layout responsive theo shell hiện tại.
- Không migration, dependency, secret hoặc thay đổi quyền PRE-006.
- Local Node 24.14.0/pnpm 11.9.0: Admin 11/11 tests, API 63/63 tests; full lint, typecheck, test, build và Prisma validation đạt.

## 5. Kiểm thử thủ công

1. Đăng nhập bằng staff ACTIVE có `report.read`; trang `/` hiển thị Admin shell sau loading.
2. Mở trực tiếp `/` khi không còn in-memory session hoặc refresh trình duyệt; ứng dụng chuyển về `/login` và không hiển thị nội dung bảo vệ.
3. Dùng role thiếu `user.manage` gọi `GET /api/v1/admin/access/users`; API trả 403. `SUPER_ADMIN` hợp lệ nhận 200.
4. Dùng token thiếu/malformed/expired/revoked gọi endpoint bảo vệ; API trả 401. Ngắt auth provider/JWKS để xác nhận state unavailable mà không làm lộ chi tiết nội bộ.

## 6. Rủi ro còn lại

- Session cố ý chỉ lưu trong memory theo IAM-001; browser refresh yêu cầu đăng nhập lại, an toàn hơn nhưng giảm tiện lợi.
- Các module nghiệp vụ phải gắn `AdminAuthGuard` + `PermissionsGuard` và permission cụ thể khi được triển khai; hai endpoint task này chỉ là contract/smoke endpoint.
- Production tiếp tục fail-closed đến `REL-001` và kiểm thử MFA trên Supabase production riêng.
