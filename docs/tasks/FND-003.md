## 2. Bối cảnh

Tech Spec §49.1 yêu cầu PR pipeline gồm: Install → Lint → Type Check → Unit Test → Prisma Validate → Migration Check → Build → Integration Test → Security Scan → Preview Deploy. Security Baseline §12 yêu cầu CI chạy secret scan và dependency scan.

ADR-001 §7 xác nhận: "Secret scanning tự động trong CI thuộc FND-003."

DEC-002 ("Xác nhận lệnh chuẩn và toolchain CI") vẫn Open, nhưng các lệnh chuẩn đã được thiết lập trong FND-001 (`pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`) và Prisma validate từ FND-005. Task này đóng DEC-002.

## 3. Mục tiêu

- GitHub Actions CI pipeline chạy trên mọi PR vào `main`.
- Pipeline bao gồm: install, lint, typecheck, test, prisma validate, build, secret scan, dependency scan.
- CI phải fail nếu bất kỳ bước nào fail.
- Pipeline chạy trên Node 24 với pnpm 11.9.0 (khớp repo).

## 4. Ngoài phạm vi

- Integration test (cần database chạy — thuộc task CI nâng cao sau).
- Migration check đối chiếu database thực (cần PostgreSQL service).
- E2E test (cần staging infrastructure).
- Preview deploy (cần hosting provider).
- Main branch deploy pipeline (thuộc REL-001).
- Branch protection rules (cần admin access, thực hiện thủ công).

## 6. User story / Use case

**Là** developer, **tôi muốn** CI tự động kiểm tra code trên mọi PR, **để** đảm bảo chất lượng và bảo mật trước khi merge.

Luồng chính:

1. Developer push code hoặc mở PR vào `main`.
2. GitHub Actions trigger workflow.
3. Pipeline chạy: install → lint → typecheck → test → prisma validate → build → secret scan → dependency scan.
4. Nếu tất cả pass → PR check xanh.
5. Nếu bất kỳ bước fail → PR check đỏ, developer sửa.

## 7. Quy tắc nghiệp vụ

1. Lockfile phải được commit; install deterministic (`--frozen-lockfile`).
2. Secret scan phải phát hiện các pattern: API key, password, private key, connection string.
3. Dependency scan phải báo lỗ hổng critical/high.
4. Không dùng credential cá nhân dài hạn cho CI.
