# PAY-006 — Payment Status UI (Sandbox)

## Scope

Build the public room-payment status page for a safe opaque payment reference created by BKG-006. It consumes only PAY-003's public-safe status contract.

## Approved behavior

- Show neutral QR payload/reference, transfer content, exact due amount and countdown for a pending unexpired payment; never display a bank account, provider transaction, raw webhook, or secret.
- Poll every 10 seconds for the first 5 minutes, then every 30 seconds. Stop polling at terminal state/unmount.
- Confirmed/paid status displays a success state and booking reference.
- Expired status shows contact support only; never offer "create payment again" in Phase 1.
- Reconciliation status displays only the approved generic message that payment is being verified, including hotline support, without internal financial detail.
- Error/loading/access-denied states must not leak whether any other payment reference exists.

## Security and verification

- Public status access uses opaque public reference only; validate format/rate limit and no direct database access from browser.
- Tests cover adaptive polling, terminal states, rendering/no sensitive fields, error/expired/reconciliation states, accessibility and mobile layout.
- Full gates and hosted CI required; no migration or dependency addition unless required by a security-safe public reference model.
