# NTF-002 — Email Adapter

## 1. Thông tin task

- **Task ID:** `NTF-002`
- **Trạng thái:** Review (`IMPLEMENTATION_APPROVED — staging-only`)
- **Dependency:** `NTF-001`, `PRE-007`
- **Mục tiêu:** Cung cấp email delivery adapter có contract kiểm thử được, Mailpit cho local/test và provider thật theo cấu hình được duyệt.
- **Điều kiện mở implementation:** Staging-only được Chủ dự án duyệt ngày 2026-08-11 với Resend, identity, `RESEND_API_KEY` reference và webhook scope. Mailpit hoặc synthetic fixture không thay thế production gate.

## 2. Phạm vi implementation sau khi gate đạt

- Email adapter interface và provider implementation theo ranh giới worker notification.
- Mailpit adapter/config chỉ cho local/test; production fail-closed nếu thiếu provider config hợp lệ.
- Chuẩn hóa kết quả delivery và phân loại lỗi retryable/permanent để NTF-001 xử lý retry/dead-letter.
- Timeout, correlation/provider message reference và log đã che PII.
- Template rendering contract kỹ thuật với synthetic template trong test; không tự soạn nội dung vận hành production.

## 3. Ngoài phạm vi

- Zalo adapter (`NTF-003`), booking notification orchestration (`NTF-004`) và reminder T-7/T-3/T-1 (`NTF-005`).
- Quy tắc retry/dedup mới ngoài contract NTF-001, gửi email trong transaction booking hoặc rollback booking khi email lỗi.
- Tự chọn provider, from address, nội dung production hoặc DNS/domain configuration.

## 4. File ownership

- Được sở hữu: email adapter/provider/test dưới worker notification và Mailpit-only config trực tiếp được task duyệt.
- Không migration/database verification; integration resource tách biệt với các lane khác.
- Không được chạm: Prisma schema/seed, `apps/web`, IAM, booking/payment hoặc Zalo implementation.

## 5. Đầu vào PRE-007 tối thiểu

- Provider email được chọn, environment/sandbox identifier và tài liệu API/SMTP chính thức.
- From name/address, reply-to và domain gửi đã duyệt.
- Trạng thái xác minh domain/DNS cho production và owner thực hiện.
- Secret-manager/reference theo environment; không ghi API key/password vào Git hoặc task spec.
- Provider limits, timeout/rate-limit guidance và webhook/bounce scope nếu có; phần ngoài task phải tách task riêng.

### Exception staging-only được duyệt

- Staging dùng Resend test mode hoặc Mailpit local; `RESEND_API_KEY` chỉ được lấy từ Railway Variables/runtime, không ghi giá trị vào Git.
- Production phải fail-closed khi thiếu provider config hợp lệ hoặc domain `vuonmangden.vn` chưa xác minh SPF/DKIM.
- `NTF-002` chỉ chuẩn hóa trạng thái `sent`/`rejected` từ response Resend. Bounce/complaint webhook không thuộc task này và sẽ vào `NTF-007` hoặc OPS task sau.

## 6. Security và tests bắt buộc

- Contract/unit: success, timeout, authentication failure, rate limit, retryable 5xx và permanent rejection.
- Mailpit integration: kiểm tra recipient/subject/body kỹ thuật và không có external delivery.
- Production-negative: Mailpit/synthetic config bị từ chối trong production; thiếu provider config phải fail closed.
- Không log body email, token, credential hoặc địa chỉ đầy đủ; correlation ID và provider reference được giữ an toàn.
- Regression: lỗi gửi không rollback nghiệp vụ; adapter không phá dedup key/routing của NTF-001.
- Full lint, typecheck, test, build và worker startup/integration smoke.

## 7. Definition of Done

- Adapter contract độc lập provider, có Mailpit local/test và provider path được duyệt.
- Retryable/permanent errors rõ ràng; booking không bị rollback do delivery failure.
- Không phát hành nội dung email production chưa được duyệt.
- PR qua required GitHub checks, kèm manual test, security impact và rủi ro provider còn lại.

## 8. Bằng chứng implementation — 2026-08-11

- Thêm email adapter ở Worker với contract độc lập provider. Resend gọi REST API bằng `fetch` native, chỉ đọc `RESEND_API_KEY` khi runtime và trả kết quả `sent` cùng provider message ID; phản hồi bị từ chối được phân loại `rejected` cho delivery tracking của NTF-001.
- Mailpit chỉ sử dụng SMTP local/test. Integration test khởi tạo SMTP server tương thích Mailpit trên loopback để kiểm tra recipient/subject/body kỹ thuật và không có external delivery.
- Authentication failure, rate limit, timeout và lỗi 5xx được phân loại retryable/permanent; riêng SMTP 4xx là retryable, SMTP 5xx là `rejected` permanent. Service giữ correlation ID, provider reference và trạng thái lỗi đã che PII, không log email body, recipient hay credential.
- Production bị từ chối hoàn toàn tại runtime trong lane staging-only này. Việc bật lại phụ thuộc `REL-001`, project production riêng và xác minh SPF/DKIM cho `vuonmangden.vn`; không có secret hoặc cấu hình production được commit.
- Không tạo migration hoặc API. Không thay đổi retry/dedup của NTF-001; caller nhận `EmailDeliveryError.retryable` để áp dụng queue retry/dead-letter hiện có.
- Local quality gates đạt: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`; Worker 27/27 tests đạt. Còn chờ Pull Request required checks trước khi task có thể chuyển Done.
