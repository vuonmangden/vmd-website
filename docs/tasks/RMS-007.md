# RMS-007 — Public Room Pages (Sandbox)

## Implementation

- **Branch:** `codex/rms-007-public-room-pages`
- **Status:** Review; no migration or dependency addition.

## Scope

Create mobile-first public room listing and room detail pages using only the existing server-side availability and price APIs with approved synthetic data. Pages must never connect directly to Prisma/Supabase from the browser and must clearly avoid claims based on real venue inventory, prices, or imagery.

## Required behavior

- List only active synthetic room types; room detail uses a stable public slug.
- Search availability by check-in/check-out and guests using the API. Empty, loading, error, and unavailable states are required.
- Display only safe room-type content: name, synthetic description, capacity, bed configuration, amenities, and a clearly labelled sandbox price quote when supplied by the price engine.
- Do not display actual room numbers, staff notes, blocks, holds, booking IDs, database IDs, or unapproved venue images.
- A booking call-to-action must carry selected room type/date/guest inputs to BKG-006; it must not create a booking on this task.

## Excluded

- Real content/photos/inventory/pricing, payment, booking creation, checkout, admin, CMS, and SEO artifacts.

## Tests and Done

- Server/API contract tests plus web tests for rendering, loading/error/empty states, accessible labels, and mobile navigation.
- Full lint/typecheck/test/build and hosted CI pass; no migration or dependency addition.
