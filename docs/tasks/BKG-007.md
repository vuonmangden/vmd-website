# BKG-007 — Booking Lookup (Sandbox)

## Scope

Public room-booking lookup uses booking code plus normalized Vietnamese phone. Both must match the same booking/customer. It is a public, server-side, anti-IDOR flow using synthetic data only.

## Approved rules

- Five failed attempts lock source IP for 15 minutes. Wrong code, wrong phone and missing booking return the same "not found" response.
- Response includes only: booking code/status, room type/count, stay dates/nights, guest count, total/paid/remaining VND, pending payment expiry, special requests, created date, masked phone/email.
- Never return status history, bank account, raw payment data, physical room IDs/codes or another customer's information.
- Pending unexpired booking can reopen PAY-006 with its opaque payment reference.
- Confirmed/paid booking confirmation is printable HTML only; PDF is excluded.
- Cancellation/date-change requests create `PENDING_REVIEW`; Receptionist can review/note, Manager approves/rejects. No self-cancel, self-confirm payment or guest data edit.
- Support values use configured app settings when available, otherwise the approved synthetic/demo contact values supplied by owner.

## Required model/API

- Add a forward-only schema/migration for booking change/cancellation requests with immutable request/audit/outbox records as required.
- Public lookup and public request creation must be rate limited, input validated and use stable errors.
- Internal review/approval endpoints require server-side permissions and audit; approval uses BookingStateService transactional transition.

## Verification

- Tests for correct/wrong phone, enumeration resistance, IP lockout/expiry, masking, safe projection, payment link eligibility, printable confirmation eligibility, request lifecycle/permission/audit/transaction safety.
- Full lint/typecheck/test/build, migration validation and hosted CI.
