# IAM-001 — Staff Authentication

## 1. Thông tin task

- **Task ID:** `IAM-001`
- **Trạng thái:** Backlog (`PLANNING_ONLY`)
- **Dependency:** `FND-004`, `FND-005`, `PRE-007`
- **Mục tiêu:** Xác thực nhân viên bằng Supabase Auth và thiết lập actor context tin cậy cho API/admin.
- **Điều kiện mở implementation:** `PRE-007` được duyệt với đầy đủ checklist tại mục 5; synthetic data không thay thế điều kiện này.

## 2. Phạm vi implementation sau khi gate đạt

- Luồng đăng nhập/đăng xuất/refresh và `GET /auth/me` theo Tech Spec §27.1.
- Admin nhận access token từ Supabase; API tự xác minh JWT và lấy `auth_user_id`.
- Adapter xác minh JWT fail-closed; kiểm tra chữ ký, issuer, audience, expiry và token type phù hợp.
- Load staff profile từ database ứng dụng và gắn actor context phía server.
- OpenAPI, error contract và correlation ID cho endpoint auth.
- Màn hình admin login tối thiểu với loading/error state; không hiển thị chi tiết lỗi nhạy cảm.

## 3. Ngoài phạm vi

- Role/permission matrix và permission seed (`IAM-002`).
- Bảo vệ toàn bộ admin route (`IAM-003`), audit service (`IAM-004`) và security middleware tổng thể (`IAM-005`).
- Tài khoản khách public, social login hoặc tự đăng ký nhân viên.
- Tự quyết định magic link, token lifetime hoặc chính sách MFA production.

## 4. File ownership

- Được sở hữu: auth module/test dưới `apps/api`, auth client/login route liên quan dưới `apps/admin`, `packages/auth` và config/test trực tiếp được task phê duyệt.
- Migration/schema chỉ được phép khi task implementation ghi rõ và IAM giữ độc quyền migration/database verification trong wave.
- Không được chạm: `apps/web`, worker notification, booking/payment hoặc provider email.

## 5. Đầu vào PRE-007 tối thiểu

- Supabase project/environment identifier cho development/staging và production; không ghi secret vào Git.
- JWT issuer, audience và JWKS endpoint/reference đã duyệt.
- Admin domain, callback/redirect URL và allowed origins theo từng environment.
- Chốt email/password; xác nhận magic link bật hay tắt.
- Chính sách access/refresh session và rotation; cách revoke phiên.
- Quy trình enrollment/recovery MFA cho Super Admin và Accountant; role assignment vẫn thuộc `PRE-006`/`IAM-002`.
- Vị trí secret-manager/reference và owner vận hành, không cần cung cấp secret trong task spec.

## 6. Security và tests bắt buộc

- Unit: thiếu/malformed/expired token, sai signature/issuer/audience, JWKS lỗi và token hợp lệ.
- Integration: Supabase sandbox/test project, profile không tồn tại/bị khóa, refresh/revoke và actor context.
- Security: mặc định từ chối; không tin role/user ID từ frontend; không log token, OTP hoặc secret; auth failure có correlation ID và structured log đã che PII.
- E2E tối thiểu: admin login/logout, refresh rotation và truy cập `/auth/me`; UI có loading/error state.
- Full lint, typecheck, test, build; migration/OpenAPI verification khi áp dụng.

## 7. Definition of Done

- Contract §27.1 hoạt động và API tự xác minh danh tính.
- IAM-002 có thể dùng actor context nhưng IAM-001 không cấp quyền nghiệp vụ.
- MFA production không bị bỏ qua; nếu chưa có enrollment evidence thì không được go-live.
- PR qua required GitHub checks và có hướng dẫn kiểm thử thủ công, security impact, rủi ro còn lại.
