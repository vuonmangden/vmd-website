## 2. Mục tiêu

Triển khai xác thực nhân viên qua Supabase Auth theo Tech Spec §34. API xác minh JWT, load staff profile và role, gắn actor context cho các endpoint admin.

## 3. Phạm vi

### Trong phạm vi

- Migration tạo bảng `staff_members` với liên kết `auth_user_id` (UUID từ Supabase).
- NestJS AuthModule: Supabase JWT verification guard.
- StaffService: load/create staff profile từ `auth_user_id`.
- Auth controller: `GET /auth/me` trả profile + role.
- CurrentUser decorator để inject actor context.
- Unit tests cho guard, service, controller.

### Ngoài phạm vi

- RBAC/permission matrix (IAM-002).
- Admin route protection (IAM-003).
- MFA enforcement (cấu hình trên Supabase, không cần code).
- Frontend login UI.

## 4. Yêu cầu kỹ thuật

### 4.1 Database — bảng `staff_members`

| Cột | Kiểu | Ghi chú |
|-----|------|---------|
| id | UUID (default gen_random_uuid) | PK |
| auth_user_id | UUID | Unique, FK logic tới Supabase auth.users |
| email | citext | Unique, NOT NULL |
| full_name | VARCHAR(255) | NOT NULL |
| role | VARCHAR(50) | NOT NULL, default 'reception' |
| is_active | BOOLEAN | default true |
| created_at | TIMESTAMPTZ | default now() |
| updated_at | TIMESTAMPTZ | auto-update |

Roles: `super_admin`, `manager`, `reception`, `marketing`, `accountant` (§33).

### 4.2 Auth flow (§34.2)

1. Frontend gửi Bearer token (Supabase access token).
2. API verify JWT signature bằng Supabase JWT secret.
3. Extract `sub` → `auth_user_id`.
4. Load `staff_members` WHERE `auth_user_id` AND `is_active = true`.
5. Gắn staff vào request context.
6. Reject nếu không tìm thấy staff hoặc inactive.

### 4.3 Endpoints

- `GET /auth/me` — trả staff profile (id, email, fullName, role).

### 4.4 Environment variables

- `SUPABASE_URL` — Supabase project URL.
- `SUPABASE_JWT_SECRET` — JWT secret để verify token.
