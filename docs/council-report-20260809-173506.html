Lộ trình tăng tốc Vườn Măng Đen — Phase 1

LLM Council · 09/08/2026 17:35 (Asia/Bangkok)

Câu hỏi

Các task nào cần làm tiếp theo để đẩy nhanh tiến độ mà không vi phạm dependency, bảo mật, migration ownership và quy tắc dữ liệu giả lập?

Phán quyết

Không mở feature lane ngay. Trước hết phải làm PR MNT-002 #1 có thể merge, chạy GitHub-hosted CI, thiết lập branch protection và đóng review cho FND-003, FND-005, BKG-001, NTF-001.

Song song lúc này chỉ nên làm ba việc: xử lý baseline/CI, thu thập bằng chứng PRE thật, và tạo readiness matrix cùng task fixture giả lập độc lập. Khi từng dependency row xanh, mới mở tối đa ba lane: IAM-001, CMS-005, NTF-002.

Việc đầu tiên

Làm MNT-002 PR #1 mergeable bằng CI GitHub có thẩm quyền và branch protection, rồi đóng các foundation review gates.

Thứ tự đề xuất

  1. Baseline: MNT-002, CI, branch protection, FND-003/FND-005/BKG-001/NTF-001.
  2. Tạo readiness matrix và task fixture giả lập có production fail-closed.
  3. Thu thập PRE thật, ưu tiên PRE-006/PRE-007 rồi PRE-001–PRE-005.
  4. Sau gate: chạy ba lane độc lập IAM-001, CMS-005, NTF-002.
  5. Identity spine: IAM-001 → IAM-002 → IAM-003/IAM-004 → IAM-005.
  6. Booking spine: RMS-001 → RMS-002 → RMS-003/RMS-004 → RMS-005/RMS-006 → BKG-002 → BKG-003 → BKG-004 → BKG-005.
  7. Payment và nghiệp vụ tài chính chỉ sau booking, authorization và dữ liệu thật liên quan.

Phân tích đầy đủ

Contrarian

Không mở ba feature branch khi nền tảng còn Review. Hoàn tất CI/protection và merge ancestry trước; dành lane song song để chốt PRE thật. Synthetic fixture phải có task riêng và không thay thế PRE.

First Principles

Nút thắt là baseline chưa ổn định. Khi baseline hoàn tất, IAM-001, CMS-005 và NTF-002 là ba lane tạo leverage tốt nhất; chuỗi booking phải đi sau IAM và RMS.

Expansionist

Tận dụng ba lane độc lập để vừa mở critical path IAM, vừa tạo public demo nhìn thấy được, vừa hoàn thiện email sandbox. Giữ migration và DB verification tuần tự.

Outsider

Mỗi task dùng synthetic phải có spec nói rõ môi trường, guard và giới hạn. Không ưu tiên Payment, BBQ hay dashboard khi booking core và quyền chưa ổn định.

Executor

Đóng baseline, sau đó chạy IAM-001/CMS-005/NTF-002. Xây vertical slice booking theo API/domain/database trước UI; không chạy đồng thời task migration.

Peer review highlights

Cả 5 reviewer chọn lập luận thận trọng là mạnh nhất. Blind spot chung: chưa có readiness matrix thực thi được, merge protocol, migration owner, isolated verification database và tiêu chí rollback.
